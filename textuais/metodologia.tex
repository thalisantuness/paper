\chapter{Metodologia}\label{metodologia}
%==============================================================================

Este capítulo descreve os procedimentos metodológicos empregados para o desenvolvimento e a validação do framework proposto. A metodologia adotada classifica-se como uma pesquisa experimental e aplicada em Engenharia de Software voltada a Sistemas Inteligentes (\textit{Software Engineering for AI}), estruturada sob os preceitos do ciclo de desenvolvimento de sistemas baseados em agentes e avaliação empírica de desempenho computacional.

\section{Caracterização da Pesquisa}

A pesquisa é orientada pelo paradigma de \textit{Design Science Research} (DSR), no qual um artefato computacional funcional é concebido, implementado e rigorosamente avaliado para solucionar um problema prático relevante: a ineficiência de custos de tokens e latência em agentes autônomos. O percurso metodológico é decomposto em quatro etapas consecutivas:

\begin{enumerate}
    \item \textbf{Modelagem Arquitetural}: Definição conceitual dos módulos, componentes e interfaces de comunicação do agente inteligente;
    \item \textbf{Implementação do Protótipo}: Desenvolvimento do framework em linguagem Python, integrando módulos de busca vetorial (RAG), serviços de inferência acelerada (Groq) e APIs de modelos de fronteira;
    \item \textbf{Configuração dos Cenários Experimentais}: Seleção de conjuntos de dados e tarefas analíticas orientadas a conhecimento para benchmarking controlado;
    \item \textbf{Avaliação Empírica e Análise de Métricas}: Execução de baterias de testes comparando a solução proposta com baselines arquiteturais clássicos com relação a consumo de tokens, custo financeiro, latência e taxa de acerto.
\end{enumerate}

\subsection{Camada de Percepção e Interface}
Responsável por capturar a solicitação do usuário, validar sintaxe inicial e receber eventuais restrições orçamentárias (e.g., cota máxima de gasto ou latência limite).

\subsection{Pipeline de RAG Enxuto}
Para evitar a transmissão de volumes volumosos de dados que saturam a janela de contexto, o pipeline de RAG atua como um filtro pré-cognitivo:
\begin{enumerate}
    \item Os documentos da base corporativa ou do domínio sob teste são convertidos em vetores densos através de um modelo leve de \textit{embedding};
    \item Realiza-se busca por similaridade de cosseno contra a consulta $x$;
    \item Aplica-se um filtro de relevância por limiar de similaridade ($\tau_{\text{sim}}$), mantendo apenas os $k$ trechos com pontuação acima do corte. Com isso, trechos irrelevantes não são despachados para a LLM, economizando centenas de \textit{input tokens} por requisição.
\end{enumerate}

\subsection{Orquestrador e Roteador Adaptativo (Ciclo C-A-F)}
O núcleo do framework baseia-se no loop Contexto-Ação-Feedback formalizado pelo ACRouter \cite{lance2026agentasrouter}:
\begin{itemize}
    \item \textbf{Triagem Acelerada no Provedor Groq}: Em vez de despachar a análise inicial para um modelo caro, o orquestrador submete o prompt enxuto a uma LLM compacta hospedada na infraestrutura Groq. Graças à velocidade da LPU (tempo de resposta medido em centenas de tokens por segundo), a classificação de complexidade da instrução é executada em frações de segundo com custo inferior a 0,0001 dólares.
    \item \textbf{Cálculo de Incerteza e Complexidade}: O sistema avalia se a tarefa pode ser concluída diretamente no Tier 1 (Groq) ou se envolve raciocínio de alta profundidade (e.g., depuração de código não determinístico ou síntese cruzada complexa).
    \item \textbf{Escalonamento Condicional}: Se o score de complexidade superar o limiar pré-estabelecido ($\theta_{\text{comp}}$), a consulta é roteada para o Tier 2 (Modelo de Fronteira). Caso contrário, a resolução gerada pelo modelo LPU é validada e retornada.
    \item \textbf{Módulo Verificador}: Analisa a consistência estrutural da resposta (e.g., cumprimento de formato JSON exigido, ausência de erros declarados). Se a resposta do Tier 1 for considerada incompleta pelo verificador, ocorre o re-escalonamento dinâmico para o Tier 2.
\end{itemize}

\section{Ambiente de Implementação e Tecnologias}

Para concretizar a arquitetura descrita, foram selecionadas as seguintes tecnologias:

\begin{itemize}
    \item \textbf{Linguagem e Framework Base}: Python 3.11 com bibliotecas assíncronas para controle de concorrência e requisições HTTP de baixa latência;
    \item \textbf{Infraestrutura de Inferência Rápida}: API Groq acessando modelos \textit{open-weights} de última geração (família Llama 3 / Mixtral) sobre hardware LPU;
    \item \textbf{Provedor de Modelos de Fronteira}: APIs de modelos comerciais de alta capacidade analítica (Tier 2);
    \item \textbf{Banco Vetorial e Embeddings}: Base vetorial em memória (e.g., ChromaDB / FAISS) acoplada a geradores de representações densas para recuperação local rápida.
\end{itemize}

\section{Procedimento de Avaliação e Métricas}

A eficácia da abordagem proposta será avaliada por meio de experimentação comparativa contra três \textit{baselines}:
\begin{enumerate}
    \item \textbf{Baseline Homogêneo de Fronteira (Always-Frontier)}: Todas as tarefas são processadas exclusivamente pelo modelo de fronteira;
    \item \textbf{Baseline Homogêneo Econômico (Always-Groq)}: Todas as tarefas são processadas exclusivamente pelo modelo de inferência rápida LPU;
    \item \textbf{Baseline Estático por Heurística}: Roteamento baseado em classificação estática de palavras-chave simples sem ciclo de verificação.
\end{enumerate}

Para mensurar os resultados, definem-se quatro métricas quantitativas primárias:

\begin{equation}
    \text{Custo Monetário Total} = \sum_{i=1}^{N} \left( T_{\text{in}}^{(i)} \cdot C_{\text{in}}^{(m_i)} + T_{\text{out}}^{(i)} \cdot C_{\text{out}}^{(m_i)} \right)
\end{equation}

\noindent onde $T_{\text{in}}$ e $T_{\text{out}}$ representam a contagem de tokens de entrada e saída da requisição $i$, e $C$ o custo unitário por token do modelo $m_i$ selecionado.

\begin{equation}
    \text{Latência Média} = \frac{1}{N} \sum_{i=1}^{N} \Delta t_i \quad (\text{em segundos})
\end{equation}

\begin{equation}
    \text{Taxa de Sucesso / Acurácia} = \frac{\sum_{i=1}^{N} \mathbb{I}(\text{tarefa}_i = \text{sucesso})}{N} \times 100\%
\end{equation}

Adicionalmente, será avaliada a métrica de \textbf{Tempo até o Primeiro Token} (\textit{Time-to-First-Token} - TTFT), quantificando a interatividade e fluidez percebida nas respostas do assistente.
